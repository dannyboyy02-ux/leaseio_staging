The one substantive gap — server-side, per-user persistence (R13)

The spec is explicit: "in production, key them to the authenticated user's profile/preferences (server-side or per-user store) so they follow the user across devices, not just one browser." Today all three prefs persist to three localStorage keys (leaseio:sidebar:*) — so they survive logout/login on the same browser, but a second device / incognito gets defaults.

This is well-contained because the codebase already has the exact pattern to mirror: AppContext.switchWorkspace() and FirmContext write per-user state to profiles via a direct authenticated UPDATE (current_workspace_id, current_firm_id). The post-#106-consolidation profiles_update RLS policy already scopes UPDATE to the caller's own row — so no new RLS, no edge function, no new table is needed.

SidebarContext — hydrate (server-wins + one-time seed) and debounced write 
// Keep the synchronous localStorage initializers (no first-paint flash). Add:
const { user } = useApp();                 // SidebarProvider sits under AppProvider
const hydrated = useRef(false);
const timer = useRef<ReturnType<typeof setTimeout>>();

useEffect(() => {                          // reconcile to server once the profile arrives
  const s = user?.uiPreferences?.sidebar;
  if (!user || hydrated.current) return;
  hydrated.current = true;
  if (s == null) { queueWrite(currentState()); return; }   // seed once from localStorage
  if (typeof s.collapsed === 'boolean') setCollapsedState(s.collapsed);
  if (s.width != null) setWidthState(clampWidth(Number(s.width)));   // reuse guards
  setNavOrderState(validateNavOrder(s.navOrder));
}, [user]);

const queueWrite = useCallback((next) => {                 // debounced, atomic sub-key write
  if (!user?.id) return;                                   // logged-out → localStorage only
  clearTimeout(timer.current);
  timer.current = setTimeout(() => {
    void supabase.from('profiles')
      .update({ ui_preferences: { ...(user.uiPreferences ?? {}), sidebar: next } })
      .eq('id', user.id);                                  // RLS scopes to own row; fire-and-forget
  }, 600);
}, [user]);
// call queueWrite({collapsed,width,navOrder}) from toggleCollapsed/setWidth/setNavOrder
// (after the existing localStorage persist). width writes on setWidth only — never previewWidth.
// clear/flush timer on unmount + signOut.

Part B · Portfolio Intelligence — the strategic reframe

This is a re-platforming of the page's premise, not a re-skin.

The design's first line: "deliberately NOT lease accounting — no Right-of-Use / ASC-842, no discounted lease liability, no PV." But today's Portfolio page is built entirely around totalPVLiability — a discounted lease liability, the exact ASC-842-flavoured math Hard Rule #1 says LeaseIO must never compute. The redesign swaps discounted liability → contractual cash commitment ("Remaining Commitment… do not PV it"), pulling the page back onto the product's stated positioning. Because of that, the new page most likely replaces the PV page rather than sitting beside it (see Open decisions).

The redesign is also strictly observational, never advisory: surface facts (rates, dates, escalations); no "renegotiate," no projected savings, no market comps. The $/sqft benchmark is the portfolio's own blended average — deliberately avoiding any external data that would need a licence or citation. This matches LeaseIO's "human-in-the-loop, not a compliance tool" rules cleanly.

portfolioIntelligence.ts — pure selector (no PV, no discounting) 
// Maps a leases row → the shape the cards consume. annualRent normalizes
// base_rent_amount by base_rent_frequency (or current_monthly_rent * 12).
export interface PortfolioLease {
  id: string; propertyName: string;
  department: string | null;     // requesting_department → "Unassigned" if null
  region: string | null;         // market bucket
  squareFootage: number | null;  // extracted + validated
  annualRent: number | null;     // derived
  start: Date | null; end: Date | null;          // lease_start / lease_end|executed_expiry_date
  escalationRate: number;        // escalation_rate ?? 0 (flat — label it)
  status: string;
}

export function computeKpis(leases: PortfolioLease[]) {
  const active = leases.filter(l => l.status === 'active' && l.annualRent != null);
  const annualOccupancyCost = sum(active, l => l.annualRent!);
  const withArea = active.filter(l => l.squareFootage && l.squareFootage > 0);
  const totalSqft = sum(withArea, l => l.squareFootage!);
  return {
    annualOccupancyCost,
    remainingCommitment: sum(active, remainingContractedRent),   // today→end, w/ escalation; NOT PV'd
    blendedPerSqft: totalSqft ? sum(withArea, l => l.annualRent!) / totalSqft : null,
    totalSqft, marketCount: new Set(active.map(l => l.region).filter(Boolean)).size,
    walt: rentWeighted(active, l => yearsUntil(l.end)),          // Σ(yrs×rent)/Σrent
    missingArea: active.length - withArea.length,                // → "N leases missing area" banner
  };
}
buildWatchlist() — declarative rules engine (2 live, 2 pending extraction) 
export type Flag = {
  leaseId: string; severity: 'warning'|'info'|'muted';
  icon: string; title: string; description: string; value: string;
  department: string | null; sourceField: string;   // provenance → "View lease" anchor
};

const RULES: WatchRule[] = [
  earliestTermExpiry,     // ✅ live — uses lease.end
  highestCostPerSqft,     // ✅ live — uses squareFootage + annualRent
  renewalNoticeDeadline,  // ⏳ pending — needs structured renewalOptions.noticeDeadline (today: free text)
  escalationCapExpiring,  // ⏳ pending — needs structured escalation cap end-date
];

export function buildWatchlist(leases: PortfolioLease[], config: WatchConfig): Flag[] {
  return RULES.flatMap(rule => rule(leases, config))
    .sort(bySeverityThenDate)
    .slice(0, config.cap ?? 8);          // "view all" beyond the cap
}
// Adding a rule = adding one entry. Thresholds (noticeWindowDays, highCostFactor)
// live in config so they're admin-tunable. Empty → "No flags — every lease term is clear."
Rent Commitment Forecast — year bucketing 
// For each of the next ~5 years (+ '31+ tail):
//  contracted = Σ rent payable that year (escalated), → 0 after each lease's end
//  uncontracted = today's run-rate that is no longer under contract that year (labelled baseline)
function forecastByYear(leases: PortfolioLease[], horizon = 5) {
  const years = range(thisYear(), thisYear() + horizon);
  return years.map(yr => ({
    yr,
    contracted: sum(leases, l => rentInYear(l, yr)),        // escalated; 0 once yr > l.end
    uncontracted: sum(leases, l => runRateRollingOff(l, yr)),
  }));
}

Voice guardrail — resolve one inconsistency in the design files

The authoritative README.md is strict: observational, never advisory; no "renegotiate," no projected savings; the $/sqft reference line is the portfolio's own blended average, no external market comps. But portfolio.jsx carries stale framing — the function is named Opportunities() and its top comment mentions "cost-vs-market benchmarking and savings opportunities."

Implement the README, not the JSX comments: name it Watchlist, keep every flag factual (dates/rates only), no market comps, keep the "Not financial advice" footer. Flagging so the stale wording isn't carried into production.
