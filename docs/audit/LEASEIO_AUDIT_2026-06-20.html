Executive summary

The honest headline: LeaseIO is much closer to done than it feels. The "always 10% away" sensation is real, but it's a convergence problem, not a foundation problem — and convergence problems are fixable in weeks, not rebuilds.

✓ Verdict — finish, don't start over

A rewrite would discard ~88% genuinely-built, tested, working code to escape problems that aren't in the foundation. The evidence:

  • TypeScript typecheck: clean (0 errors). 971 tests passing, 0 failing — covering the load-bearing logic (approval chains, entitlements, RLS governance, lifecycle, audit trail).
  • CI is genuinely strong: typecheck + tests + security smoke + a Postgres migration-replay job + a Node⇄Deno mirror-parity gate. Better discipline than most funded startups.
  • The app is real: ~80k lines of frontend, 62 edge functions (several 700–2,800 lines of real logic), 49 tables with real RLS, working Stripe + three-tier Claude pipeline. Not a prototype in costume.

Why it feels "always 10% away"

  1. Too many parallel fronts at 80–95%. Firm layer, firm billing, email intake, market data — each new front resets the "almost done" clock before the last one hard-closes. Biggest driver.
  2. Polish debt sprayed thin across 6–8 surfaces. Each nit is small; collectively the product feels unfinished. This audit concentrates them so they can be fixed as batches, not whack-a-mole.
  3. Doc-drift. When the status docs can't be trusted (this audit found #103's server side is far more complete than the docs say), nothing feels done even when it is.

A · Format & layout consistency

This theme is the "inconsistent across formats/layouts" complaint, made concrete. The same value — money, a date, a status — is rendered differently depending on which component you're looking at. Fixing it is mostly one shared-helper change with high visible payoff.

A1 Currency is formatted nine different ways across the app HighINCONSISTENCYVerified ✓ ▶
Where
ApprovalQueue.tsx:64 · LeaseRequestForm.tsx:500 · RentScheduleTable.tsx · SummaryStrip.tsx · LeasePipeline.tsx · RentRollExport.tsx · Reports.tsx · CommitmentHistory.tsx · ai-assistant/index.ts:27
What
At least nine distinct money-formatting paths coexist: toLocaleString('en-US'), raw toLocaleString(), locale-aware formatLocalizedCurrency(), formatCurrency() vs formatCurrencyDecimals(), formatCompactCurrency() ($1.2M), CSV-with-cents, and two en-AU sites. Some respect the EN/ES language toggle; most don't.
Why it matters
A user sees $50,000 on the dashboard, $50,000.00 in the CSV, $1.2M in a chart, and a Spanish-locale figure in the rent schedule — for the same number. It reads as "unfinished," and it generates "why is this different?" support questions from finance users who care about exactly these details.
Fix
Add one formatMoney(amount, {compact?, decimals?, language}) in src/lib/dateFormatters.ts (extend the existing formatLocalizedCurrency), then replace all call sites. Policy: UI = locale-aware, no decimals; exports = explicit 2-dp (documented in the export header).
A2 Australian (en-AU) locale used for US currency/dates LowBUGVerified ✓ ▶
Where
Reports.tsx:321, 323 · CommitmentHistory.tsx:50, 102
What
Four sites pass 'en-AU' to toLocaleString/toLocaleDateString. Verified — and broader than the first scan suggested (the scan found Reports only).
Why it matters
Almost certainly copy-paste drift. Output is usually identical to en-US, so it hides — but it's a latent locale bug and a trivial, satisfying win.
Fix
Replace with en-US (or route through the A1 shared helper, which removes the literal entirely).
// Reports.tsx:321,323 — both lines
Pipeline: ${Number(lease.monthly_payment||0).toLocaleString('en-AU')}/mo
Executed: ${Number(lease.executed_monthly_payment||0).toLocaleString('en-AU')}/mo
A3 Dates rendered in four different formats MediumINCONSISTENCYVerified ✓ ▶
Where
Leases.tsx:329 & AuditLog.tsx:327 (MMM d, yyyy) · RentRollExport.tsx:47 (MM/dd/yyyy) · Portfolio.tsx:322 (YYYY-MM string-slice) · LeaseAudit.tsx:55 (browser toLocaleDateString)
What
Four date styles in the UI. MM/dd/yyyy in the CSV is intentional (spreadsheet standard); the others are accidental drift, and LeaseAudit's output even changes with the viewer's browser locale.
Why it matters
Scannability and trust. The portfolio register's 2023-06 → 2026-06 is the odd one out and is harder to read at a glance than Jun 2023 → Jun 2026.
Fix
Standardize all UI dates on MMM d, yyyy via a shared formatDate(); keep the CSV explicit and documented.
A4 The same lease status shows different badge colors on different screens MediumINCONSISTENCYVerified ✓ ▶
Where
LeaseStatusBadge.tsx · LifecycleStatusBadge.tsx · AuditLog.tsx:214 (getStatusBadgeColor) · workflow.ts:61 (WORKFLOW_STATUS_CONFIG)
What
At least four independent mappings from status→color. AuditLog even uses fragile substring matching (status.includes('failed')), which would also match a hypothetical partially_failed.
Why it matters
An "Approved" lease is one color in the list and another in the audit log. Status color is a primary scanning cue for finance users; divergence undercuts trust in the whole UI.
Fix
One getStatusBadgeVariant(status) + a single <StatusBadge> consumed everywhere; delete the substring matcher. See the A4 mockup.
A5 Percentages mix .toFixed(0) and .toFixed(1) LowINCONSISTENCYVerified ✓ ▶
Where
ExtractionAnalytics.tsx:267 (92.5%) · LeaseAudit.tsx:360 (92%) · Reports.tsx:329 (12.3%)
What & fix
Pick one precision for each metric class (confidence/quality = 1 dp; variance/share = 0–1 dp) and apply consistently. Folds naturally into the shared-formatter pass.

B · Bugs / correctness

B1 "Needs review" low-confidence warnings can never fire — the column they read is never written HighBUGVerified ✓ ▶

⚠ Scanner overstatement corrected

The automated pass claimed this banner falsely flags every field as low-confidence. Reading the code shows the opposite: the banner's low-confidence branch never fires at all, because its data source is empty. Both are bugs — but the real one fails silent, not noisy, and the fix is different. This is exactly why High findings get hand-verified.

Where
NeedsReviewBanner.tsx:22,48 · LeaseReview.tsx:332 · workflow.ts:24 · LeaseReviewSections.tsx:51 · process_lease/index.ts
What
Two parallel confidence systems exist, on two scales:
  • Banner path (0–100): reads lease.confidence_scores and flags fields below 80. But a repo-wide search shows confidence_scores is only ever read (LeaseReview.tsx:332) and never written by any code path — process_lease writes none. So it's always {}, and the low-confidence warning is dead.
  • Badge path (0–1): the per-field ConfidenceBadge reads the live extracted_json[field].confidence (0–1) and works correctly.
Why it matters
The "review low-confidence fields before posting" gate is a core human-in-the-loop safety promise — and it's silently inert. A user can post a lease with a 0.55-confidence landlord name and get no warning, because the badge is easy to miss and the banner is dead.
Fix
Re-point the banner to the live source: use getFieldConfidence(extracted_json, field), unify on the 0–1 scale with a 0.80 threshold, and drop (or properly populate) the dead confidence_scores column. See the B1 mockup.
// NeedsReviewBanner.tsx — reads a column nothing populates
const score = confidenceScores[field.key];           // from lease.confidence_scores → always undefined
return score !== undefined && score < 80 && fieldValues[field.dataKey];

// LeaseReview.tsx:332 — the only reference to the column anywhere
return (lease?.confidence_scores as ConfidenceScores) || {};   // nothing writes it

Portfolio.tsx:62 · Leases.tsx:285 · LeaseAudit.tsx:47 · portfolioAnalytics.ts · SummaryStrip.tsx:86 (already uses getCurrentMonthlyRent)

C · Dead-ends & stranding

States a user can enter but not cleanly exit. These hurt disproportionately — one dead-end can sink confidence in an otherwise-working flow.

C1 A failed lease with no stored file strands forever — no re-upload button HighDEAD-ENDVerified ✓ ▶
Where
FailedLeaseBanner.tsx:98–102
What
When extraction fails and storage_path is missing, the banner shows "Original file not available for retry. Please upload a new document." — next to a {/* TODO */} and no upload control. Retry is disabled. The lease sits in Failed with no exit.
Why it matters
The UI tells the user to do something the UI gives them no way to do. It's the textbook dead-end, on an error path users already arrive at frustrated.
Fix
Render an "Upload New Document" button (opens the existing upload modal) whenever !canRetry. See the C1 mockup.
// FailedLeaseBanner.tsx:98-103 — today
{!canRetry && (
  <p className="text-xs mt-2 text-muted-foreground">
    {/* TODO: Allow re-upload when storage_path is missing */}
    Original file not available for retry. Please upload a new document.
  </p>   // ← no button. the user is stuck.
)}
C2 A request whose approval routing failed sits in draft with no retry MediumDEAD-ENDVerified ✓ ▶
Where
LeaseRequestForm.tsx:345–360 → LeaseReview.tsx
What / why
If resolve-approval-chain errors/times out, the lease is saved as draft with a toast, then the form closes. On the detail page there's no "Retry routing" CTA, so a transient failure looks permanent — and users may re-upload, creating duplicates.
Fix
On LeaseReview, when a lease is draft with no submitted_for_approval_at, show a banner + "Retry routing" that re-invokes the chain resolver.

Where

Stripe idempotency mitigates an actual double-charge, but the anxiety and support contact are real.

D · Firm / billing surfaces

The firm layer (Phases 9–10) is well-built and the billing server is guarded better than the docs claim. The residual issues are mostly UI affordances that should be hidden, plus consistency.

D1 Firm-bound workspaces still show billing buttons the server rejects MediumPOLISHVerified ✓ ▶

✓ Scanner overstatement corrected — and good news for #103

The scan rated this High ("duplicate-subscription billing hole"). Reading the edge functions shows the server is guarded fail-closed: create-checkout (line 64), customer-portal (line 64), and manage-document-pack (line 207, covering its real modes confirm/buy_single) all reject firm-bound workspaces with firm_managed. There is no buy_subscription mode (the scan invented it). So this is a Medium UI-polish issue, not a billing breach — and it means KNOWN_ISSUES #103's server side is essentially closed; only the client affordances remain.

Where
LimitReachedDialog.tsx:350 · AccountSettings.tsx:1140 (UI) — guards in create-checkout / customer-portal / manage-document-pack
What
"Buy a pack", "Buy single", and "Update payment method" still render on firm-bound workspaces. Clicking them hits a 403 firm_managed — correct safety, confusing UX.
Why it matters
The user is offered a door that's wired to a wall. Better to hide it and explain that the firm owns billing.
Fix
Hide these controls when workspace.firmId is set; add a short "Billing is managed by {firm}" note. Then update #103 + CLAUDE.md to record that the server side is closed. See the D1 mockup.

Remediation roadmap

Ordered for leverage and to impose convergence discipline — close a phase fully (code + tests + docs + review) before opening the next. Effort is rough developer-days. Every code phase routes through the mandated review subagents (auditor + security always; integrity for data paths; polish for UI).

P0 · Quick wins & safety — ~1–1.5 days

  • B1 re-point confidence banner to live data (restores the audit-gate warning).
  • C1 FailedLeaseBanner "Upload New Document" CTA.
  • A2 kill the four en-AU literals. E2 npm audit fix + retest.
Routes: code-auditor, security-scanner, product-polish (C1), test-author. Reviewers: integrity (B1 audit gate).

P1 · The consistency pass (kills the core complaint) — ~2–3 days

  • A1/A3/A5 shared formatMoney() + formatDate(); replace all call sites.
  • A4 single getStatusBadgeVariant() + one <StatusBadge>; delete the substring matcher.
  • B3 single getMonthlyRent(lease) helper; reuse in all 5 sites.
Highest visible payoff for "it finally looks finished." Routes: auditor, polish, test-author (formatter + selector unit tests).

P2 · Firm / billing UI lockdown + read-only — ~2 days

  • D1 hide firm-bound billing controls + "managed by firm" note; then E3 reconcile #103/CLAUDE.md (server side closed).
  • C3 firm-checkout success toast + redirect to FirmBilling.
  • D2 thread read-only gating through all intake affordances. D3 per-member role-save feedback.
Routes: security-scanner (authz affordances), integrity (billing entitlement paths), polish.

P3 · Dead-ends & polish cleanup — ~1.5 days

  • C2 retry-routing CTA · C4 contextual empty states · C5 document URL-only routes.
  • B4 verify + fix RentRoll status filter · B5 tighten annual-obligation fold.
  • D4 plan-control signpost · D5 de-hardcode firm price · D6 shared firm header.

P4 · Hygiene & durability — ~1.5 days

  • E1 split the Deno ESLint config (lint becomes a real gate). F1 summarize AI context packet.
  • E4 one Playwright happy-path e2e (request → review → approval → repository).

Operating principle (the actual cure for "10% away")

Close before you open. Each phase ends only when code + tests + docs + reviewer sign-off all match reality — then the next begins. This converts the fan of 80%-done branches into a stack of 100%-done ones, which is what makes a build feel finished.
