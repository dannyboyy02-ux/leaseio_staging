2What the conventions actually are

Column resize & auto-fit

From AG Grid (which explicitly mirrors Excel): "just like Excel, each column can be auto-resized by double-clicking the right side of the header rather than dragging it… the grid will work out the best width to fit the contents of the cells in the column." Double-click = autosize-to-content is a learned, cross-tool muscle memory. Reset-everything is not what that gesture means.

Where reset / column controls live

Enterprise-table guidance: give users a reset safety net, but "controls … shouldn't feel overwhelming and can be tucked into a simple 'table settings' dropdown or highlighted on hover while keeping the default view clean." Auto-fit / reset / pin / hide belong in a per-column menu or a table-settings menu — not as standing toolbar buttons.

Dates

"Use the abbreviated name of the month, such as 17 Jan 2025… Avoid short numeric format dates as different countries use different date orders." So Mar 1, 2026 is the right style — the defect is that it isn't localized.

Alignment

"All numbers should be right-aligned … numeric data related to size (count, percent, money) should be right-aligned to help users identify number size; numeric data not related to size (date, zip, phone) should be left-aligned. Everything made of letters is left-aligned."

Sources are linked in the chat message that accompanies this file.

4Fix: double-click = auto-fit that column P1

Replace "double-click → reset everything" with "double-click the divider → size this column to its widest cell." The fit-to-100% model we already have means an auto-fit grows this column and gives the space back proportionally from the others, so the table still fits — no horizontal scroll.

Interaction

Property Landlord Rent
1450 Mission St, Suite 200, San Francisco…Five Degrees, LLC…$77,646

⟶ user double-clicks the green divider on Property ⟶ Property widens just enough to show the full address; Landlord & Rent give up a sliver each. Total stays 100%.

How "widest cell" is measured: every header & body cell for a column carries a data-col attribute; on double-click we read the cells' scrollWidth (the natural, un-truncated width), take the max, convert to a % of the table, and rebalance.

// new pure helper in src/lib/leaseColumnPrefs.ts (unit-tested)
export function autoFitColumn(
  widths: ColumnWidths, key: LeaseColumnKey, targetPct: number,
): ColumnWidths {
  // clamp the target, then take the delta proportionally from the OTHER
  // resizable columns (never below MIN) so the total stays 100 → still fits.
  const desired = clampPct(targetPct);
  const delta = desired - widths[key];
  return redistribute(widths, key, delta);   // shared with applyBoundaryResize
}

// in Leases.tsx — measure the rendered column, then call the helper
const autoFit = (key: LeaseColumnKey) => {
  const table = tableRef.current; if (!table) return;
  const cells = table.querySelectorAll<HTMLElement>(`[data-col="${key}"]`);
  let max = 0;
  cells.forEach((el) => { max = Math.max(max, el.scrollWidth + CELL_PADDING_PX); });
  const targetPct = (max / table.offsetWidth) * 100;
  setColumnWidths((w) => autoFitColumn(w, key, targetPct));
};

// the divider's handler swaps reset → auto-fit (the conventional gesture)
- onDoubleClick={resetColumnWidths}
+ onDoubleClick={() => autoFit(key)}
Honest tradeoff to pick (see §11): our table promises "always fits," but auto-fit-to-content can ask for more than the viewport (a very long address). Two options: (A) keep the fit promise — auto-fit grows the column up to what's available, capping so the table never scrolls (recommended); or (B) match Excel exactly — auto-fit to true content width even if it introduces a horizontal scroll. I recommend A because "make it fit" was your original ask.

5Fix: a column menu, and reset moves into it P2

Drop the standing "Reset columns" toolbar button. Put the column controls where people look for them: a small caret on each header (and/or right-click), opening a tiny menu. This also advertises that columns are adjustable — solving the discoverability gap in one move.

Per-column menu (caret / right-click)

↔Auto-fit this column
⤢Auto-fit all columns
↕Sort ascending
↺Reset columns to default

Why this shape

  • Auto-fit this / all — the discoverable version of the double-click gesture (and keyboard-reachable, which the drag handle is not).
  • Reset — still here as the safety net, just not shouting from the toolbar.
  • Toolbar goes back to: search · scope · type · expiry · export. Cleaner default view.

Built on the existing DropdownMenu primitive (same one the row kebab and Export use), so no new dependency. Reset stays gated to "only when layout ≠ default."

They converged on a single root cause and ~15 issues. Headline: forcing all 10 columns to fit a ~974px table shrinks every column below its content, and px-4 cell padding (32px × 10 cells = 320px of pure padding) eats what's left — so dates, Sq Ft and Status get 36–46px of usable space and clip, and the cells that forgot overflow-hidden spill into their neighbor. That one decision spawns the SF redundancy's clip, the date clip, the icon-only headers, and the Archived↔kebab overlap.

10The rule I'm writing for myself

Why I missed these: I built bespoke table interactions and judged them against my own intuition instead of against the tools every finance user already has muscle memory for (Excel, Sheets, every data grid). I'm adding a Data-table conventions checklist to .claude/agents/lease-product-polish.md so any table change gets measured against the established pattern first:

  • Resize: drag a border to resize; double-click a border auto-fits that column to content (Excel/AG Grid). Never repurpose double-click for "reset all."
  • Column controls (auto-fit, reset, pin, hide) live in a per-column or table-settings menu — not standing toolbar buttons. Reset is a safety net, kept quiet.
  • Alignment: right-align size numbers (money, counts, %, sq ft); left-align text and non-size numbers (dates, IDs, zip, phone); headers align to their column's content.
  • Dates: abbreviated-month medium format (Mar 1, 2026), never bare numeric (03/01/26 is locale-ambiguous), and always through the canonical locale-aware formatter — never a hardcoded date-fns format string (it silently breaks i18n).
  • Before inventing a table interaction, name the tool it mirrors (Excel / Sheets / a known grid). If it mirrors nothing, that's a flag, not a feature.
